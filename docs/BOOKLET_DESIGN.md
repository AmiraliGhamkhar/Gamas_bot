# Gamas booklet design system

Every AI booklet Gamas sends is a designed publication, not a Word file with a
template applied. This page documents the layer that makes that true and the
rules that keep it true.

The governing principle:

> **Content is generated by the AI; design is controlled by the Gamas document
> engine.** The language model produces semantics — headings, definitions,
> tables, warnings. It never chooses a colour, a font, a page size or a border.

## Where it lives

| Module | Responsibility |
| --- | --- |
| `gamas_bot/document/theme.py` | Every design token: palette, type scale, spacing, geometry, sizes. |
| `gamas_bot/document/components.py` | The semantic component vocabulary (callouts, tips, cards, labels, chapter numbers). |
| `gamas_bot/document/assets.py` | The asset manifest, semantic lookup and deterministic topic selection. |
| `gamas_bot/document/rtl.py` | Line-level BiDi: shaping, display order, logical-order wrapping. |
| `gamas_bot/document/typography.py` | Font faces, sizes and leading shared by both renderers. |
| `gamas_bot/document/layout.py` | A4 page geometry and the frame both outputs share. |
| `gamas_bot/document/qa.py` | Post-render inspection: PDF rasterization, DOCX structure, asset audit. |
| `assets/booklet/manifest.json` | The asset contract: path, size, role and topic for every image. |
| `scripts/build_booklet_assets.py` | Deterministic generator for the bundled artwork. |
| `scripts/render_booklet_samples.py` | Renders the three QA booklets (A/B/C) to DOCX, PDF and page PNGs. |

The two renderers — `gamas_bot/docx_export.py` (Word) and
`gamas_bot/notes_pdf.py` (PDF) — consume these modules and contain no visual
constants of their own. `tests/test_booklet_design.py` enforces that: a raw
`"#RRGGBB"` literal in either renderer fails the suite.

## Colour language

Semantic names only; the hex values live in `Palette`.

| Token | Value | Used for |
| --- | --- | --- |
| `navy_950` / `navy_900` / `navy_800` / `navy_700` | `#04202C` … `#0B4658` | Chapter banners, cover panel, table headers |
| `teal_700` / `teal_600` / `teal_500` / `teal_400` | `#087F8C` … `#3FB6C0` | Brand line, accents, subheads, rules |
| `cyan_500` / `cyan_300` | `#25C6D6` / `#9BE9EF` | Secondary accent, dark-card labels, hairlines |
| `cream_50` / `cream_100` / `paper` | `#FFF9ED` … `#F2EFE7` | Page and panel grounds |
| `ink` / `body` / `muted` | `#102B36` … `#60747C` | Text hierarchy |
| `success` / `warning` / `danger` / `info` | green / amber / red / blue | Status only |

Red is reserved: it may mark a warning, a critical distinction or a failure, and
nothing else. `test_red_is_reserved_for_warnings_and_errors` checks that no
other callout borrows it.

## Typography

* Vazirmatn Regular and Bold are bundled in `assets/fonts/` and embedded in the
  PDF; Word references the same family for both Latin and complex script.
* Body text is 11 pt with 1.55 leading — readable on A4 and on a phone.
* Persian digits throughout; Latin technical terms and formulas stay LTR.
* Shaped, not reversed: `rtl.visual()` resolves BiDi with an explicit base
  direction and `rtl.wrap_logical()` wraps in logical order *before* shaping, so
  a mixed line never breaks mid-phrase.

## Components

`components.py` names the vocabulary the renderers share:

* Blocks: `DEFINITION`, `EXAMPLE`, `FORMULA`, `HIGH_YIELD`, `KEY_POINTS`,
  `SUMMARY`, `QUOTE`, `GUIDE`, `GLANCE`, `EDITORIAL`, plus callouts (`نکته`,
  `هشدار`, `یادآوری`) and tips (`آزمونی`, `کاربردی`, `هشدار`).
* Each block owns its fill, border, accent and label — renderers ask for the
  block, never for a colour.
* `LABELS` holds the Persian section names so Word and PDF cannot drift.

Two heading registers, deliberately distinct:

* **Navy banner** — chapters, the key-points recap, the glossary. A navy bar
  always means *a major destination in this booklet*.
* **Teal display heading with a short ECG rule** — reading guide, at-a-glance,
  objectives, summary, tips, review, speakers, editorial note.

## Cover

Cream paper, navy frame, teal/cyan curves, an ECG trace, an open book, a
graduation cap, a molecule, a capsule and a document card. The artwork is a
generated PNG behind the layout; **all critical text is drawn by the renderer**
(the wordmark, title, session metadata, quote, brand line), because image
generators distort Persian script.

Topic-aware artwork is deterministic: `topic_for()` scores the booklet text
against keyword families and falls back to `general`. A tie follows a fixed
priority list, so the same lecture always gets the same cover.

| Topic | Cover | Emblem |
| --- | --- | --- |
| `medical` | `cover/hero-medical` | `icons/cross` |
| `pharma` | `cover/hero-pharma` | `icons/capsule` |
| `data` | `cover/hero-data` | `icons/network` |
| `general` | `cover/hero-general` | `icons/knowledge` |

## Pipelines

**DOCX** — `build_notes_docx(notes, meta=…)`: the existing exporter, rewired to
the theme. Cover → guide → at-a-glance → objectives → summary → chapters
(banner, source line, prose, definition cards, bullets, tables, formulas,
high-yield, callouts) → key points → tips → review → speaker/timeline →
glossary → editorial page. Real `Heading 1/2/3` styles are kept so the file
stays editable and navigable, RTL is declared through `w:bidi`/`w:bidiVisual`,
tables repeat their header row, and the footer carries a real `PAGE` field.

**PDF** — `build_notes_pdf(notes, meta=…)`: ReportLab, drawing the same
components on the same A4 frame with an invariant canvas (frame, header brand,
footer plate, page number). ReportLab has no BiDi engine and no contextual
shaping, so every line is wrapped logically, shaped once, then drawn — never
reversed as a string trick.

Both consume one theme, one component vocabulary and one asset manifest, which
is what keeps them visually aligned.

## Validation and QA

`gamas_bot/document/qa.py` inspects the artifacts after rendering:

* `inspect_pdf()` — A4 geometry, non-empty page streams, embedded Vazirmatn,
  and (when `pymupdf` is installed) rasterized pages checked for blank pages,
  blocks outside the frame and overlapping text blocks.
* `inspect_docx()` — package completeness, embedded artwork, print resolution,
  complex-script font, RTL declaration and page-number field.
* `validate_assets()` — every manifest path exists, is a plausible size and has
  a role.

`scripts/render_booklet_samples.py` renders the three representative booklets
(short Persian / long medical / mixed technical), rasterizes every PDF page to
`.render/booklet-samples/<case>/page-NN.png` and prints a PASS/FAIL summary.
It is the command used for the visual review; the PNGs are inspected by eye and
the defects are fixed in the renderer, never in the output.

## Regenerating

```bash
python -m scripts.build_booklet_assets      # artwork + manifest check
python -m scripts.render_booklet_samples    # A/B/C DOCX + PDF + page PNGs
python -m pytest tests/test_booklet_design.py tests/test_booklet_rendering.py \
                tests/test_docx_export.py tests/test_notes_pdf.py \
                tests/test_pdf_visual_qa.py -q
```

## Known limitations

* **The DOCX is not rasterized on this host.** There is no Word and no
  LibreOffice, so the `.docx` is verified structurally (package, fonts, RTL,
  borders, fields, tables, artwork) and never compared pixel-by-pixel with the
  PDF. The PDF is the rendered proof of the shared design system.
* ReportLab cannot justify RTL prose: a justified last line would jump to the
  left margin, so PDF body text is right-aligned instead. Word keeps
  justification, which it handles correctly.
* Line-level shaping means a parenthesis pair that wraps across two lines can
  look odd in the PDF; long parentheticals are therefore kept out of card
  titles, and the definition card renders the term and the definition as
  separate paragraphs.
* Artwork is generated art (Pillow), not commissioned illustration: it is
  on-brand and topic-aware, but it is not photorealistic.
